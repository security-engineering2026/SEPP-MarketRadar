## هدف نسخه v2

Manifest دارای 49 قرارداد کلان است. این نسخه آنها را به **196 واحد اتمیک (4 واحد برای هر قرارداد)** می‌شکند تا دقیقاً مشخص شود نقص در کجاست:

- **CODE-PARTIAL/ALIGNED** = کد یا ساختار موجود است ولی هنوز Definition of Done کامل نشده.
- **CODE/PACKAGING-INCOMPLETE** = خود implementation/packaging هنوز کامل یا قابل اثبات نیست.
- **TEST-MISSING/INCOMPLETE** = کد موجود است ولی regression کافی نداریم.
- **ADVERSARIAL-TEST-MISSING** = failure/security/negative test لازم است.
- **QUALIFICATION-NOT-PASSED** = در محیط مربوطه اجرا شده و سابقه failure وجود دارد یا acceptance رد شده.
- **ENV/EVIDENCE-MISSING** = تست باید در محیط دیگری اجرا شود یا evidence معتبر هنوز ثبت نشده.
- **EXTERNAL-ENV-MISSING / EXTERNAL-EVIDENCE-MISSING** = وابسته به سرویس/endpoint واقعی و credentialed است.
- **PASS** = برای همان زیرواحد evidence معتبر فعلی وجود دارد؛ PASS یک زیرواحد، PASS کل Manifest نیست.

### قانون مهم
وجود فایل، تابع، تست، یا حتی یک CI سبز **به‌تنهایی PASS نیست**. هر زیرواحد باید implementation + test + failure coverage + environment evidence + audit exposure متناسب با Definition of Done را داشته باشد.

## Failure classification

When a sub-unit fails, update it with this exact chain:

**FAIL → evidence reference → failure output → root cause → minimal patch → regression test → rerun → evidence → PASS/OPEN**

When code is incomplete:
**CODE-INCOMPLETE → reuse search → implementation → targeted test**

When code exists but test is absent:
**TEST-MISSING → write regression → run in correct environment**

When test exists but environment proof is absent:
**ENV/EVIDENCE-MISSING → route to owner environment → execute → capture evidence**

When external prerequisite is unavailable:
**OPEN / NOT EXECUTED**, never PASS.
