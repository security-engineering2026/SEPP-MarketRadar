## Purpose

This file is the **single operational queue** beside the normative Manifest. The Manifest defines what the system must mean and guarantee; this checklist defines the ordered work required to prove each requirement.

The previous 49-contract / 196-atomic-unit registers remain references. **This file is the day-to-day execution order.**

## Locked execution rules

1. **Strict order:** Row 1 is the first active row. A later row does not become active until the current row is PASS.
2. **One active work item:** only one row may be actively executed at a time.
3. **No premature implementation:** before changing code, inspect current repo/tests, MarketRadar, CDR_Core, Software_Forge, official tooling/docs, and mature OSS where relevant.
4. **No duplicate implementation:** if a proven reusable solution exists, adapt it instead of rebuilding it.
5. **PASS requires proof:** code existence alone is never PASS.
6. **Correct environment:** a requirement is not PASS until acceptance is proven in the environment that owns that claim.
7. **Failure loop:** FAIL → evidence → root cause → minimal patch → regression → retest → qualification → evidence.
8. **No side-track work:** non-blocking discoveries are recorded for later; they do not interrupt the active row.
9. **Controlled reopen:** if later work invalidates an earlier PASS, only the affected dependency chain is reopened and reverified.
10. **No guessed gaps:** exact code/test gaps are filled by inspection when the row becomes active; do not infer a code defect from missing evidence.
11. **Evidence anchor:** every PASS must point to commit, test/run, environment, and artifact/log evidence as applicable.
12. **Manifest reconciliation:** after each closed row, update the audit state before the next row starts.

## Status semantics

- **PASS:** all required acceptance/exit criteria are proven with valid evidence.
- **OPEN:** a known implementation/process gap exists and remains unresolved.
- **FAIL:** the required test/qualification was executed and acceptance failed.
- **NOT EXECUTED:** required work or evidence has not yet been run/proven.
- **SKIPPED:** intentionally not executed with a documented reason.

`Execution Gate` is separate from `Status`: rows after the active row are `WAITING — previous row not PASS`; this does not change their evidence status.

## Row closure gate

A row may move to PASS only when all applicable items below are satisfied:

- [ ] Exact Manifest mapping is confirmed.
- [ ] AS-IS was inspected in code/tests/configuration.
- [ ] Exact gap (or explicit no-gap finding) is recorded.
- [ ] Existing reusable solution was searched.
- [ ] Minimal implementation/adaptation is complete, if needed.
- [ ] Targeted acceptance test passes.
- [ ] Failure/adversarial test passes where relevant.
- [ ] Required environment qualification passes.
- [ ] Audit/reporting exposure is verified where required.
- [ ] No contradictory legacy path remains.
- [ ] Evidence anchor is recorded.
- [ ] Regression impact on previously PASSed rows is checked.
